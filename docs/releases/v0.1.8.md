# Neuron v0.1.8

Keep button mapping open when a dock loses mouse identification, and stop showing an unused Trinity on installations that never had one.

## Changes

- A failed or unavailable dock identification no longer switches away from the selected mouse workspace or discards unsaved mappings. Hardware writes remain disabled until the matching mouse is identified again.
- Fresh installations create workspaces for detected or explicitly selected mice instead of adding a default Naga Trinity.
- Upgrading hides an unclaimed Trinity workspace only when it still matches the untouched legacy default. Its files remain on disk. Customized profiles, macros, and previously connected mice are preserved.
- Explicitly clearing a dock's saved mouse choice still opens its identification workspace.

## Naga V2 Pro with Mouse Dock Pro

If the dock shows **Identify mouse**, select it in the sidebar, open **Devices**, choose **Naga V2 Pro** under **Which mouse is paired with this dock**, and click **Save mouse choice**. Return to **Button mapping**. The saved choice is specific to that connection.

## Download and upgrade

Use **Check for updates** in an installed Neuron v0.1.7, or download **Neuron-Setup-0.1.8-x64.exe**, save pending edits, quit Neuron from its tray menu, and run the installer. Existing profiles, macros, mouse selections, and original-mapping backups are retained. The installer is unsigned; **SHA256SUMS.txt** contains its checksum.

## Validation

All 125 automated tests passed. The packaged desktop workspace smoke test covers dock identification loss and recovery, preservation of unsaved mappings, and mouse selection on an empty installation. Hardware behavior was simulated; this release has not been physically verified on the reported Naga V2 Pro and dock.
